# Design Notes - MD Slice of ND Data Persistence

## Current Flow
```
_on_segment_current()
  → _segment_nd_slice(md_slice)
    → image_data_model.save_predictions(md_result, ...)
      → io.save(...)
```

## Problem
- **Segment**: Always MD (e.g., YX from ZYX)
- **Save**: Some writers natural for MD-of-ND, others awkward

## Writer Categories

### Natural MD-of-ND Writers
- `TiffSliceIO` - saves individual slices as separate files
- `ZarrArtifactIO` - sparse writes into ND array at specific indices
- Both understand: "save this MD at position Z=3"

### Awkward MD-of-ND Writers
- `TiffArtifactIO` - expects full ND array to save as single TIFF
- `NumpyArtifactIO` - expects full ND array
- Must reconstruct/load full ND, update slice, save all

## Design Questions

1. **Who reconstructs ND?**
   - Option A: Writer handles it (load full, update, save)
   - Option B: Model handles it (maintains ND array, passes to writer)
   - Option C: New "ND Manager" between model and writer

2. **Current step tracking**
   - Model gets `current_step` but writer may not use it
   - TiffSliceIO uses it to generate filename
   - Tiff/Numpy ignore it (expect full array)

3. **Interface mismatch**
   ```python
   # What we have:
   io.save(md_slice, current_step=3)

   # What awkward writers need:
   full_nd = load_existing_or_create_empty()
   full_nd[current_step] = md_slice
   io.save(full_nd)
   ```

## Thoughts

- **TiffSliceIO/ZarrArtifactIO** = incremental, sparse
- **TiffArtifactIO/NumpyArtifactIO** = full reconstruction required
- All use same interface but different semantics
- Should writers declare capability? ("supports_sparse_write")
